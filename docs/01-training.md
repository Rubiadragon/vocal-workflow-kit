# 训练用于唱歌的音色：RVC

[文档导航](INDEX.md) / 训练

## 训练的目标

RVC 学的是声音转换：输入原唱，输出目标音色。旋律、节奏、咬字、气声和不少演唱习惯仍来自输入。
它不是从文字生成旋律。若要文字讲话，使用 [GPT-SoVITS 路线](04-speech.md)。

## 1. 先准备数据

- 使用同一目标说话者、已经获得相应用途授权的干净录音。
- 去掉伴奏、其他人声、明显混响、截断、爆音与错误标签；不要把所有处理堆上去导致金属感。
- 想唱歌，就覆盖实际会使用的低／中／高音区、长音、连音、气声与不同力度；只有说话数据未必能覆盖目标唱腔。
- 可把 20–40 分钟净素材作为第一轮收集计划，实际需求取决于录音质量、音域与预训练模型，不是保证线。
- 留出没有参与训练的测试句／歌段。不要只听训练素材上的结果。
- 切片均值短不等于原录音没有长音；需要检查原始演唱和切片内容。不要从一个时长统计直接判断根因。

先整理为 PCM WAV，运行：

```powershell
python -m vocal_workflows dataset-audit "datasets/my_voice"
```

该工具检查数量、时长、声道与采样率，并用内容摘要代替文件名输出。它不能替你检查唱腔覆盖或听出噪声。

## 2. 在匹配版本的 RVC WebUI 中走完准备

1. 新建短实验名，例如 `example_voice`。不要把绝对路径填进实验名。
2. 选定模型版本和采样率，例如 v2 / 40k；之后权重、配置、F0 预训练 G/D 必须匹配。
3. 用实际数据目录做预处理，核对处理日志和有效音频数量。
4. 提取 F0（常用 RMVPE），再提取相应版本的特征。
5. 核对 `logs/<实验名>/config.json`、`filelist.txt`、特征与音高目录。
6. 在上游界面训练并定期保存，再建立该实验对应的检索索引。

本项目不代替上游预处理、特征提取和索引训练；`train-plan` 只输出最终训练命令模板，不会自动执行。

## 3. 一组起点，而不是万能参数

| 项目 | 首轮参考 | 如何调整 |
|---|---|---|
| 版本／采样率 | v2 / 40k | 与所用预训练模型和工程一致 |
| batch | 4 | 显存不足先减到2或1，不能只看显卡总容量 |
| 总轮数 | 100作为首轮观察点 | 每10–20轮留样比较，不以轮数越高越好 |
| 保存间隔 | 10轮 | 先确认当前fork实际支持该参数 |
| 学习率／segment_size | 先保留匹配上游配置 | 不为修音色问题随意改网络相关配置 |
| 索引 | 训练结束后建立并核实配对 | 推理 index_rate 从0和0.3做同位置对照 |

```powershell
python -m vocal_workflows train-plan --kind rvc --experiment example_voice --epochs 100 --batch 4
```

输出的 `argv` 是 legacy RVC v2 40k 模板；核对自己的 `train.py --help` 后才能使用。不同fork不保证参数同名。

## 4. 保存、导出与恢复

- 训练断点通常是 G/D 成对文件，包含恢复所需状态；导出的轻量推理权重不是完整断点。
- 同时保留配置、文件列表、数据版本和训练日志，防止恢复到了别的数据集。
- 正常等待完整断点写完再停止。不要在写文件途中强杀训练。
- 恢复前核对上游逻辑和日志，不猜“最大数字一定是最后一步”。实验名与日志目录必须匹配。
- 部分RVC版本自动读取该实验最新G/D断点，但不是所有fork都相同。

## 5. 用对照决定下一步

固定同一份干净输入、同一段音高与推理设置，只改变一个变量：模型轮次、index_rate或移调。
若干声本身已有背景人声或电音，先定位输入；后期EQ不能可靠修复错误音高或损坏的切片。
说话像、唱歌不像时，检查音域、持续发声和演唱数据，而不是无限加轮数。

只发布本工具和流程，不随包公开声音数据、训练G/D、推理权重或检索索引。

参考：[RVC 官方训练说明](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/wiki/Instructions-and-tips-for-RVC-training)。
